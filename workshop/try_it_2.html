Workshop · Block 4

Try it 2: the window, threads, and one plan-build-reset cycle

Where

The CLI in VS Code's integrated terminal, as in Try it 1.

Before you start

Try it 1 done (you are on tryit1), and the frontend set up (npm install in frontend/), so Claude can run the frontend tests when it builds. If you skipped the setup, tell the trainer; the fallback is below.

Do not

Add a card, change the database or seed data, or let the build grow past the plan. If Claude offers extra work, say no.

  1. Branch. In a terminal: git switch -c tryit2.
  2. See the window. Run /context. Write down the total before you have typed anything, and the biggest category.
  3. Start a thread. First name it, so you can find it later: /rename card-loading. Then send:
    Copy and paste
    Explain how a card loads its data, from Card.jsx to the backend. Keep it short.
  4. A side question. While it answers (or after), send /btw which file decides whether a card fetches data at all?. Read the overlay, then Esc. It used no tools and is not part of the conversation.
  5. A detour on a branch. Send /branch refresh-idea, then:
    Copy and paste
    What would a refresh button on every live-data card need to change? Three bullets, no code.
  6. Back to the main line. Run /resume and pick card-loading. Prove it missed the detour: /btw did we talk about a refresh button in this conversation?
  7. Plan. Shift+Tab until ⏸ plan mode on. Send:
    Copy and paste
    Add a refresh button to cards that load live data, so I can fetch new data without reloading the page.
    Answer its questions: they come as one card with a tab per question and a final "Review your answers" screen; press Enter on "Submit answers". Read the plan. At the approval menu, press Esc: the plan stays saved in plans/, and nothing is built.
  8. Reset by hand. Run /clear. Press Shift+Tab until ⏵⏵ accept edits on (from plan mode it passes through auto and manual first). Edits go through; commands still ask. Send:
    Copy and paste
    Build the plan in @plans/<your plan's file name>.md.
    Type @plans/ and pick the file from the list. Approve the commands it asks to run (reading files, running the tests, checking its own work). If it asks to start the dev servers for a browser check, choose No: that stops the turn, and the work so far stays.
  9. What did the fresh chat know? /btw what do you know about why this plan was written? It knows the plan file, not the conversation that made it.
  10. Commit. commit my changes with a descriptive message, or commit yourself.
Done looks like

The second chat built the change from the plan file, and you can say what it knew (the plan) and did not know (your detour, your side questions, the planning conversation).

Where this goes

The capstone (Block 9) scales this hand-off up: its control-tower file is this plan file, one size up, carrying a whole feature across fresh sessions.

The shortcut

This repo turns on the setting that offers "Yes, clear context … and use auto mode" at the plan menu. It does steps 7-8 in one choice. Doing it by hand once shows what it does for you.
